Private build of cmux · macOS + iPhone

Your terminal on your iPhone, over your own tailnet.

hmux is cmux with the cloud taken out. The Mac app and the iPhone app talk to each other directly over Tailscale, paired with a one-time code. No cmux account, no relays, no telemetry.

Set it up View on GitHub

Requires macOS 14 or later, iOS 17 or later, Tailscale on both devices, and an Apple Developer account to sign your own builds.

Why this exists

The official cmux connects the iPhone app to the Mac through a cmux account and Iroh relays run by the cmux service. That is convenient, but it puts a third-party service between your phone and a terminal on your own infrastructure.

hmux keeps the connection between your devices. The Mac listens on one TCP port that only Tailscale addresses can reach, and the iPhone proves itself with a key the Mac issued to it. Everything that would talk to cmux.com is switched off at build time.

What's different from cmux

Kept

  • The full cmux terminal, built on Ghostty
  • Workspaces, splits, the sidebar and agent integrations
  • The embedded browser and Markdown viewer
  • iPhone remote view and control of your Mac's terminals
  • The automation socket and cmux CLI

Removed or switched off

  • cmux account sign-in Stack Auth, on both apps
  • Iroh relays and control servers
  • cmux Cloud machines and the VPN tunnel extension
  • Device discovery, presence and push notifications
  • Auto-update Sparkle never starts
  • Analytics, crash reports and remote feature flags PostHog, Sentry
  • Billing and the feedback uploader

On the Mac these are cmux's own administrator policies, which a local-only build forces on. They show as locked in Settings. On the iPhone the account is replaced by a fixed on-device identity, and every cloud address points at a closed port on the phone itself.

How it works

  1. The Mac shows a one-time code. It is a QR code with the Mac's Tailscale addresses, the port and a secret. It works once, expires after five minutes, and burns after five wrong guesses.
  2. The iPhone redeems it. The phone connects to the Mac's Tailscale address and trades the code for its own random device key, which it stores in the Keychain for that exact address and port.
  3. Every request carries the key. The Mac keeps only a SHA-256 hash of each phone's key in a file only your user can read, and refuses requests without a valid key. Revoking a phone takes effect on its next request.

Traffic between the devices is end-to-end encrypted WireGuard. When Tailscale can't connect the devices directly, it routes them through its relay servers. Those servers see only encrypted packets. To avoid them, allow direct connections on your router or run your own relay.

Setup

You build and sign both apps yourself. Plan for about an hour the first time, and at least 30 GB of free disk space: a full cmux build leaves large temporary folders behind.

  1. Install the tools

    • Xcode 27.1 or later, opened once to finish its setup, plus the Metal toolchain
    • zig 0.16.0, Go and Rust
    • Tailscale on the Mac and the iPhone, signed in to the same tailnet
    • An Apple Developer account with a Developer ID Application certificate (Mac) and a development profile that lists your iPhone
    • An App Store Connect API key, so the Mac build can create its own Developer ID provisioning profile
    xcodebuild -downloadComponent MetalToolchain
brew install go rust
# zig 0.16.0 from https://ziglang.org/download/ (Homebrew may ship another version)

  2. Get the source

    git clone https://github.com/devicemanager/hmux.git
cd hmux
git submodule update --init --recursive

  3. Write your local settings

    Your team ID, bundle IDs, signing identity and server details live in .env-local, which git ignores. The template explains every setting.

    cp .env-local.template .env-local
open -e .env-local

    To notarize the Mac app, store notarytool credentials once and put the profile name in CMUX_LOCAL_NOTARY_PROFILE:

    xcrun notarytool store-credentials my-notary-profile \
  --apple-id you@example.com --team-id TEAMID --password app-specific-password

  4. Build the Mac app

    This builds a Release copy and registers your Mac bundle ID with Apple if needed. It creates a Developer ID provisioning profile, signs and notarizes the app, then installs hmux in /Applications. It installs under your own bundle ID and never replaces the official cmux.

    Without the profile the app can't keep secrets in its own Keychain group, and macOS refuses to launch a Developer ID app that claims one. Run scripts/build-local-only-mac.sh --skip-build to re-sign the last build without compiling again.

    scripts/build-local-only-mac.sh

    Open hmux, then turn on iOS pairing in Settings › Mobile. The pairing listener uses TCP port 4399.

  5. Build the iPhone app

    Over the air: set CMUX_LOCAL_IOS_OTA_DIR to a folder your HTTPS web server publishes and CMUX_LOCAL_IOS_OTA_URL to its public address. Then open <url>/install.html on the iPhone in Safari.

    ios/scripts/build-local-only.sh

    By cable instead: connect and unlock the iPhone, then pass its identifier.

    xcrun devicectl list devices
ios/scripts/build-local-only.sh --device-id <identifier>

    The iPhone must have Developer Mode on (Settings › Privacy & Security) and be listed in the signing profile.

  6. Pair

    • On the Mac: open Pair your iPhone and click Show Pairing Code.
    • On the iPhone: open hmux, go to Add Computer and scan the code within five minutes.

  7. Check what leaves your Mac

    With the phone connected, the only sockets should be the listener and your phone's Tailscale address:

    lsof -nP -a -p "$(pgrep -f 'hmux.app/Contents/MacOS' | head -1)" -i

    On the iPhone, turn on Settings › Privacy & Security › App Privacy Report. After a day of use it lists every domain and address hmux contacted. It should show only your Mac. For proof over longer periods, run a per-app firewall such as LuLu or Little Snitch on the Mac.

Managing paired iPhones

Run these in a terminal inside hmux. Each pairing creates one entry, so pairing again after reinstalling the app leaves the old entry behind.

cmux rpc mobile.local_devices.list
cmux rpc mobile.local_devices.revoke '{"id":"<device id>"}'

Troubleshooting

The iPhone says the Mac runs an incompatible version of cmux

The phone has an older build that only accepts official Mac releases. Install the current iPhone build; local-only builds accept any cmux build on your Mac.

The pairing code is rejected

Each code works once and expires after five minutes. Click New Code on the Mac and scan again.

The iPhone can't reach the Mac

Check that Tailscale is connected on both devices and that the Mac is listening:

tailscale status
lsof -nP -iTCP:4399 -sTCP:LISTEN

If nothing listens, turn on iOS pairing in Settings › Mobile.

"Provisioning profile is Xcode managed, but signing settings require a manually managed profile"

The iPhone script avoids this by building unsigned and signing with codesign. If you see it, you are building through Xcode directly; use ios/scripts/build-local-only.sh.

The Mac app won't open ("Launch failed", error 163)

The app claims an entitlement its provisioning profile doesn't grant. Set the App Store Connect key in .env-local and run scripts/build-local-only-mac.sh --skip-build.

The build stops with "No space left on device"

Delete old build folders in ~/Library/Developer/Xcode/DerivedData and the .build folders under Packages/, then rerun. Free space can take a while to show up when Time Machine keeps local snapshots.

The phone doesn't use my Pi-hole or other DNS server

With Tailscale on, the phone sends DNS to Tailscale. Make the DNS server reachable from the tailnet and set it under DNS in the Tailscale admin console. hmux itself makes no DNS lookups: it connects to your Mac by numeric address.
